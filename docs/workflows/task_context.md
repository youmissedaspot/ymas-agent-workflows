# Compact task context and resume

Version: v1

Keep a short task-specific projection of existing authority when a handoff, interruption
or complex task needs it. Use the existing task/receipt location; this is an optional aid,
not a new document family or a second authority register. A small settled edit needs only
its relevant clauses. Link full evidence instead of duplicating logs in task/state/next.

Record only what the next action needs:

- Request, latest steering, authorized scope, exclusions and acceptance owner/process.
- Repository/base/current commit and tree, branch/worktree owner, dirty-work ownership;
  selected qualified skill, package version and contract path/digest when ambiguity matters.
- Governing paths, editions/hashes and relevant clauses; accepted decisions and their
  acceptance sources; unresolved consequential questions and dependent work stopped.
- Affected owners, interfaces, callers, cross-system invariants and dependencies. Link
  dependent contracts even when another team/system owns them. An omitted dependency
  does not disappear. Expand to full authority when freshness/coverage is uncertain.
- Expected/observed behavior, cheapest meaningful verification, detailed receipt link,
  results/limits, current blocker and one next authorized action.
- Failed unit/cause/reproduction, source change, count and stop/reassessment reason;
  uncertain operation identity, owned resources and cleanup obligations.

Layer retrieval: lean instruction/index pointers → task context and owning clauses →
full owning/dependent contracts when needed → raw evidence/history for a specific
question. Check hashes/editions against current sources before relying on a packet.
For a larger corpus, see [optional concept-to-source navigation](source_navigation.md).
If stale or conflicting, reconcile/regenerate it. Never let a summary override authority,
erase accepted qualifications, reopen settled choices or manufacture permission.

After compaction or interruption, preserve latest user steering, acceptance boundaries,
known stops, per-unit failures, pending operation identity and owned resources. Recheck
live Git and operation state before acting. Do not replay an uncertain mutation or
retry a known blocker. Complete independent authorized work while dependent work stops.

## Roles and selected contracts

Describe responsibilities as implementer, verifier/reviewer, decision owner and integration
owner. One person/agent may fill more than one role where the project permits; independent
review remains independent when required. Model/effort/tool preferences are configurable
task or repository choices, recorded once with their source. Do not mandate a vendor,
change the current preference to manufacture savings, infer a new review requirement
from a model name or treat technical verification as project-owned human acceptance.

When same-name skills differ, follow the user's explicit selection and the repository's
designated qualified package/contract. Inspect available path/version instead of choosing
by name, timestamp or cache folder alone. If a material conflict cannot be resolved by
existing authority, surface it and stop only dependent work. Installation does not adopt
the package; do not remove personal skills or edit a cache to resolve ambiguity.

## Experiments, with authority preserved

A complete specification inventory may record every current ID/path, version/hash,
acceptance status, owner, interface, invariant and dependency. It supports retrieval and
freshness checks. It does **not** replace the existing complete current SPEC/SPECARC
review after substantive specification changes. Reduced-text review needs an explicitly
adopted, evidence-backed process; test seeded cross-system conflicts before proposing it.

Optional local measurement on authorized replay tasks: record package/source identity,
model/effort, permissions, task/risk class, setup/work time, outcome/corrections, validated
review findings and escaped defects. Record supported aggregate input/cache/output usage,
returned-document characters and compaction counts **only where exposed**; missing is
unknown. Keep total/subtotal semantics explicit to avoid double counting. Compare matched
cases under unchanged authority/model/effort/permissions and report setup cost and limits.
Returned text is a proxy, not billed usage or allowance savings. No fixed saving is claimed.
Do not gather private sessions, raw reasoning, credentials or personal content. This aid
contains no collector, background task, persistent access or telemetry transmission.
